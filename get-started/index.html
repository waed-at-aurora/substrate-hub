02 · Get started@aurora-ui/components-v2 v1.0.20

From zero to a rendered component.

Six steps: check the environment, install the package, wire styles and theme, render a component, connect the tooling, and verify. Nothing here duplicates the API docs — component-level detail lives in Storybook.

Setup — six steps

  1. Prerequisites and supported environments

    React 18 or 19 with react-dom, and react-i18next as peer dependencies. Inside the aurora-ui monorepo you consume the workspace package; outside it you need access to Aurora’s private CodeArtifact registry. For the guided CLI path: Node ≥ 20 and an authenticated GitHub CLI (gh auth login); AWS CLI v2 only for a real (non-dry-run) install. Windows is supported natively.

  2. Install the Substrate package

    Guided path: the Substrate CLI (prototype) inspects your environment and runs the real AWS and npm steps, each gated by a confirmation (or --yes). It never prompts without a TTY, so agents can drive it too.

    Guided — check, preview, then install
    npx --yes github:AuroraEnergyResearch/substrate-cli-v2 doctor
npx --yes github:AuroraEnergyResearch/substrate-cli-v2 install --dry-run
npx --yes github:AuroraEnergyResearch/substrate-cli-v2 install
    Manual — inside the monorepo, package.json
    "dependencies": {
	"@aurora-ui/components-v2": "workspace:packages/components-v2"
}

    Outside the monorepo, use the guided CLI install — it handles the private-registry authentication for you. npx against the private CLI repo needs gh auth login.

  3. Import styles, theme, and tokens

    One stylesheet carries tokens, base styles, and component styles, all inside CSS cascade layers so your app’s own CSS keeps precedence. Theme is a class on the root element: .dark (what this hub runs) or .light (the package default).

    Root of your app
    import '@aurora-ui/components-v2/style.css';

<html className="dark"> … </html>

  4. Render a first component

    Anywhere in your tree
    import { Button } from '@aurora-ui/components-v2';

<Button variant="eos">Run scenario</Button>

    Steer it live in Fig. 2 on the overview — every option change re-renders the real package.

  5. Install and configure the CLI

    substrate-cli (prototype) does three things: installs the design system, raises feedback as GitHub issues, and reads component documentation offline from a bundled snapshot — usage prose and real prop tables without opening Storybook.

    Run via npx — always tracks main, no install step
    npx --yes github:AuroraEnergyResearch/substrate-cli-v2 doctor
    Or put a `substrate` binary on your PATH — packaged release
    gh release download v0.1.0 --repo AuroraEnergyResearch/substrate-cli-v2 --pattern '*.tgz'
npm install -g ./aurora-ui-substrate-cli-0.1.0.tgz
    Read docs from the terminal
    substrate docs component --list
substrate docs component Button
substrate docs topic design-principles

    Working with a coding agent? substrate skill install copies the CLI’s agent skill into ~/.claude/skills/substrate-cli/ so Claude-compatible agents drive it automatically. Avoid npm install -g github:… — a known npm bug breaks global git installs; use npx or the release tarball above.

  6. Verify

    The button renders in EOS yellow, form fields pick up zinc borders, and no custom CSS was needed. If something looks unstyled, work through the checks below.

Substrate is pre-1.0: minor versions may move fast. Before upgrading, read releases → 05 for breaking changes and migration actions, and validate against the canonical Storybook. For contribution and cross-repo validation workflows (source-link, snapshots), follow DesignSystemConsumerWorkflows.
