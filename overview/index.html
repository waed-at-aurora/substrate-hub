What Substrate isshared interaction layer · product-owned experiences

A common way to solve recurring product interactions.

Substrate sits between low-level UI foundations and complete EOS experiences. It packages shared decisions into reusable composite components and documented patterns, so teams start from established behavior instead of recreating the same interaction.

Room above

Product variants remain possible above the shared system. Differentiate at the product layer; never fork the shared one.

The UX core

Substrate doubles down on the layer typical design systems leave to product flows: reusable composite components and interaction patterns. It is the highest-leverage UX work for building with AI — 9 composites and 49 primitives today.

The shared foundation

Substrate also includes UI primitives and EOS tokens. Most design systems cover this foundation well; here it makes the composite UX layer dependable rather than defining the highest-value work.

Manual, inside the aurora-ui monorepo — package.json
"dependencies": {
	"@aurora-ui/substrate": "workspace:packages/substrate"
}
First import
import { Button } from '@aurora-ui/substrate';
import '@aurora-ui/substrate/style.css';

The Substrate CLI (prototype) also checks environments, files feedback issues, and reads component docs offline — full setup in get started → 02.
